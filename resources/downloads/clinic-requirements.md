# Clinic website requirements checklist

Separate a public information website from any system that handles clinical records.

## Public information
- [ ] Verified practitioner qualifications and specialties, approved by the clinic.
- [ ] Accurate address, opening hours, contact route and accessibility information.
- [ ] Clear appointment request process and response expectations.
- [ ] Emergency communication reviewed by the clinic; a form is not emergency care.
- [ ] Consent and permissions for photography and testimonials.

## Appointment workflow
- [ ] Define request versus confirmed booking.
- [ ] Define scheduling owner, cancellations and duplicate handling.
- [ ] Collect only essential contact data.
- [ ] Agree any messaging provider, consent and costs.

## If sensitive records are proposed
- [ ] Confirm applicable privacy requirements with an appropriate adviser.
- [ ] Define identity verification, roles and access logs.
- [ ] Agree private storage, encryption, retention and deletion handling.
- [ ] Establish tested backup/recovery and incident procedures.
- [ ] Never place patient records in a public repository or analytics.

## Handover
- [ ] Clinic approval of all factual content.
- [ ] Domain and provider-account ownership.
- [ ] Document recurring hosting, messaging, support and maintenance costs.
- [ ] Test mobile usability and real appointment handling with synthetic data.

This is a technical scoping template, not legal or clinical advice.
