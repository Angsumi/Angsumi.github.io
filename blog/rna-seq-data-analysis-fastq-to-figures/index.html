RNA-seq data analysis: from FASTQ to figures

By Angsuman Das · Published 18 November 2026

Bulk RNA-seq analysis turns raw sequencing reads (FASTQ files) into a table of genes that change between conditions. The core steps are quality control, alignment or quantification against a reference, building a count matrix, statistical testing for differential expression (for example with DESeq2), functional enrichment, and figures that report effect sizes and uncertainty.

This guide follows that path from beginning to end for a typical bulk RNA-seq experiment. Single-cell RNA-seq, de novo transcriptome assembly and long-read data each need a different workflow. For a broader review of design and analysis choices, see Conesa and colleagues' survey of best practices for RNA-seq data analysis.

1. Start with the design, not the data

Before you open a FASTQ file, write down the comparison you want to make. List the groups, the biological replicates in each group, any pairing (for example the same patient before and after treatment), and the batches in which samples were extracted, prepared and sequenced.

This matters because the statistical model is built from this table. If every control sample was sequenced in one batch and every treated sample in another, the treatment effect and the batch effect cannot be separated, and no software can recover that comparison. On replication, Schurch and colleagues tested replicate numbers systematically in yeast and recommended at least six biological replicates per condition.

2. Check read quality

Run FastQC on every FASTQ file and summarise the reports with MultiQC. Look for:

  • per-base quality falling sharply towards the read ends
  • adapter content
  • unexpected overrepresented sequences, such as ribosomal RNA
  • samples whose read counts or GC content differ clearly from the rest

FastQC flags are prompts to investigate, not automatic failures. RNA-seq libraries routinely show duplication and composition patterns that FastQC marks as warnings. Trim adapters and low-quality bases with a tool such as fastp when the reports justify it, and record the settings you used.

3. Align or quantify against a reference

There are two standard routes:

  • Alignment-based. A splice-aware aligner such as STAR or HISAT2 maps reads to the genome and writes BAM files. You then count reads per gene with featureCounts. BAM files also support visual inspection and other downstream uses.
  • Quantification-based. Salmon estimates transcript abundance directly from reads without writing full alignments. Its transcript-level estimates are summarised to genes with tximport.

Either way, record the exact genome assembly and annotation release (for example the Ensembl or GENCODE version). Results are only reproducible against the same reference.

4. Build and inspect the count matrix

The count matrix has one row per gene and one column per sample. Pair it with a sample sheet whose identifiers match the column names exactly.

Before testing anything, look at the samples as a whole. The DESeq2 vignette shows how to apply a variance-stabilising transformation and draw a PCA plot and a sample-distance heatmap. These plots reveal sample swaps, outliers and batch structure. A sample that clusters with the wrong group deserves an explanation before analysis continues.

5. Test for differential expression

DESeq2 models raw counts with a negative binomial distribution and estimates size factors to account for differences in sequencing depth. You supply a design formula, such as ~ batch + condition, that names the variables to adjust for and the one you want to test.

Points that often go wrong:

  • Input type. DESeq2 expects raw or estimated counts, not TPM, FPKM or other normalised values.
  • Multiple testing. Thousands of genes are tested at once. Report adjusted p-values, which DESeq2 calculates with the Benjamini–Hochberg procedure, rather than raw p-values.
  • Effect size. Fold changes estimated from low counts are noisy. Shrinkage estimators such as apeglm give more stable values for ranking and plotting.

edgeR and limma-voom are well-documented alternatives. Choose one method, state the version, and avoid running several methods only to report the most convenient result.

6. Interpret the results

A list of significant genes is rarely the final answer. Common next steps are:

  • Over-representation analysis, which asks whether a pathway appears in your significant gene list more often than expected. The background ("universe") should be the genes that were actually tested, not the whole genome.
  • Gene set enrichment analysis (GSEA), which uses the full ranked list rather than a significance cut-off.

Enrichment results depend on the annotation database and its version, so record both. Enrichment describes association with a gene set. It does not show that a pathway is active or that it causes the phenotype.

7. Make figures that report uncertainty

Standard RNA-seq figures each answer a specific question:

  • PCA plot: do samples group by biology, by batch, or neither?
  • Volcano plot: how do effect size and statistical evidence relate across all genes?
  • MA plot: do fold changes depend on expression level?
  • Heatmap: how do selected genes behave across individual samples?

Label axes with units and transformations, say in the caption which test and threshold were used, and show sample counts. Our scientific figure quality checklist lists further checks.

8. Make it reproducible

Record software versions, parameters, reference identifiers and the commands that produced each output. Workflow frameworks such as nf-core/rnaseq package many of these steps with version control (Ewels et al.). Whatever you use, another analyst should be able to rerun the work from your README. Our guide to what a reproducible bioinformatics handover should contain lists what to include.

Common questions

Can I start the analysis from a count matrix instead of FASTQ files?

Yes, if the counts are raw (unnormalized) and you can document how they were produced, including the reference genome and annotation versions. You lose the ability to repeat read-level quality control, so keep the original FASTQ files available.

How many biological replicates do I need?

It depends on the effect sizes you care about and on biological variability. One systematic yeast study recommended at least six biological replicates per condition. Decide this before sequencing, because replication cannot be added during analysis.

Should I use DESeq2, edgeR or limma-voom?

All three are established, documented methods for count-based differential expression. The choice matters less than a correct design formula, appropriate filtering and honest reporting. Use the method whose assumptions and documentation you can follow and cite.

Are TPM or FPKM values suitable input for DESeq2?

No. DESeq2 expects raw counts or estimated counts imported with an appropriate route such as tximport. Normalized values like TPM or FPKM are not direct substitutes.
